# CantResell 공동 가구점 시제품

## 핵심 경험과 확정 범위

네 명이 한 가게를 운영하지만 일할 의무는 없다. 한 명은 손님을 상대하고, 다른 한 명은 공금을 도박에 쓰고, 또 다른 사람은 무료 놀이를 할 수 있다. 밤에는 모두 한 집에 침입해 가구를 확보한다. 서로 탓하면서도 도망갈 때는 함께 움직이는 대화가 핵심이다.

이 주제와 공금 통합, 자유로운 낮 활동, 동시 침입, 센서→신고→경찰→체포→다음 날 흐름은 사용자가 정한 내용이다. 아래 금액·시간·목표·체포 정산·4일/3밤 구성은 승인된 프로토타입의 초기 테스트값이며 재미와 밸런스가 검증된 수치는 아니다.

이야기상의 목적은 수상한 가구점을 유지하는 것이다. 시스템 목표는 마지막 영업 종료 때 공금 1,000 이상을 모으는 공동 성공이다. 개인 순위나 비밀 목표는 없다. 예를 들어 점원이 의자 하나를 팔아 25를 벌었는데 친구가 100을 잃으면 공금은 75 줄어든다. 밤에 고가 가구를 더 가져올 이유가 생기지만 경보 뒤에는 가구를 포기하고 철수할지 판단해야 한다.

## 실행

1. Unity **6000.3.25f1**에서 프로젝트를 연다. 실제 프로젝트 버전은 ProjectSettings/ProjectVersion.txt 기준이다.
2. 기존 Photon Fusion/Voice App ID와 지역 설정을 유지한다. 다른 참가자도 동일한 설정과 새 빌드를 사용한다. Photon 설정 파일을 이 작업에서 덮어쓰지 않는다.
3. `Assets/1. Scenes/Home.unity`에서 Play를 누르거나 `Builds/Windows/CantResell.exe`를 실행한다.
4. 이름을 입력하고 방 만들기에서 제목(최대 30자), 공개/비공개를 선택한다. 비공개 비밀번호는 문자·숫자 1~8자이며 공백·기호는 허용하지 않는다. 방 코드는 자동 생성한다.
5. 나머지 세 명은 방 목록에서 제목을 선택한다. 잠금 방은 비밀번호를 입력한다. 목록은 다섯 개씩 이전/다음 페이지로 볼 수 있다. 가득 찼거나 시작한 방에는 참가할 수 없다.
6. StandBy에서 색상을 고르고 네 명 모두 준비한다. 방장이 게임 시작을 누른다. **마이크 켜기**로 대화한다. 기본 마이크는 꺼져 있다. **마이크 테스트**는 입력량만 표시하고 상대에게 송신하지 않는다.
7. 네 명이 Play에 들어오면 첫날 영업을 시작한다. 별도 역할 배정은 없다.
8. 결과에서 방장이 대기실로 돌아가 재시작할 수 있다. 방 나가기는 Home으로 돌아간다.

Windows 실행 파일 네 개 또는 에디터 하나와 빌드 세 개, 또는 PC 네 대로 참가한다. 한 에디터 안의 다중 러너는 지원하지 않는다. 실제 장치 마이크와 다른 PC에서의 지연은 별도 플레이 테스트 대상이다.

## 흐름과 규칙

`1일 낮 → 1일 밤 → 2일 낮 → 2일 밤 → 3일 낮 → 3일 밤 → 4일 낮 → 공동 결과`

마지막 밤의 가구를 팔 수 있도록 마지막 낮을 둔다. 기본 제한 시간은 낮/밤 각각 180초이며 모두 시간을 사용하면 7×180=1,260초, 즉 21분이다. 전원 조기 철수하면 더 짧아진다. 목표 20~30분이 실제 플레이에서도 유지되는지는 아직 검증이 필요하다.

| 항목 | 초기 테스트값 / 처리 |
| --- | --- |
| 참가자 | 정확히 4명 |
| 공금 | 처음 300, 목표 1,000 |
| 시작 재고 | 의자·조명·테이블·수납장·소파·침대 각 1개 |
| 판매 가격 | 순서대로 25 / 35 / 50 / 60 / 80 / 100 |
| 낮 활동 | 가구 판매, 공금 도박, 무료 타이밍 놀이, 자유 이동 |
| 주문 | 실제 남은 재고 종류 중 하나, 인내 40초, 다음 입장 간격 4초 |
| 밤 재고 | 매번 8개, 6종에서 무작위로 생성 |
| 운반 | 한 명당 가구 1개, 차량 적재 후 더 가져올 수 있음 |
| 센서 | 6초 주기 중 3초 켜짐. 입구 스위치는 10초 차단 |
| 신고 | 센서 통과 시 집주인이 깨고 신고. 20초 뒤 경찰 추격 |
| 체포 | 첫 체포로 밤 종료. 공금 25% 올림 차감, 이번 밤 가구 전부 몰수 |
| 기존 재고 | 체포해도 가게에 있던 가구는 유지 |
| 시간 만료 | 밤은 자동 철수. 차량 적재품만 획득, 손에 들고 있던 것은 상실 |
| 종료 | 마지막 낮 종료 때 목표 이상이면 전원 성공, 미달이면 전원 실패 |

낮에는 주문 종류의 가구를 들어 계산대에 가져가 E로 판매한다. 다른 종류는 판매할 수 없다. 시작 재고를 전부 팔아도 `300+350=650`이므로 목표에는 350이 더 필요하다. 안전한 판매만 하고 모든 침입을 건너뛰는 목표 우회를 막는 초기 가격이다. 재고가 없으면 새 수입은 도박 승리나 다음 밤의 확보 후 판매에 의존한다. 손님을 놓쳐도 추가 벌금은 없다.

밤에는 하나의 집을 자동 지정한다. 네 명이 동시에 차량 앞에서 시작한다. 출입문 E, 센서 스위치 E, 가구 E로 들고 차량에서 E로 적재한다. 빈손으로 차량에서 E를 누르면 철수하며 그 밤에 다시 들어갈 수 없다. 한 명만 철수해도 남은 사람이 체포되면 적재 가구 모두 몰수된다. 신고 후 센서를 다시 끄더라도 이미 한 신고는 취소되지 않으며 경찰 도착 시간도 늦어지지 않는다. 경찰 도착 시 문은 강제 개방된다.

공금 0은 즉시 패배가 아니다. 남은 재고를 판매하거나 밤에 더 확보해 복구할 수 있다. 누군가 이를 다시 도박으로 잃게 하는 것도 허용한다. 참가자 이탈은 경기 중단으로 처리한다. 탈락자만 따로 기다리는 모드는 없다.

## 공금과 선택

공금은 별도 개인 지갑 없이 모든 판매·도박·벌금에 쓰인다. 장부는 최근 8건을 전원에게 보여 누가 얼마를 벌고 잃었는지 알 수 있다. 가구 종류·가격·위치·운반자, 센서 상태·신고 카운트다운·철수 상태도 모두 공개한다. 이 시제품에는 숨겨야 할 상품 원가나 개인 목표가 없다.

| 경로 | 공금에 미치는 영향 |
| --- | --- |
| 시작 | 한 번 300 생성 |
| NPC 가구 판매 | 가격만큼 새 돈 생성, 가구 소비 |
| 가구 도둑질 | 돈 생성 없음. 물품이 집→차량→공동 재고로 이동 |
| 도박 패배 | 베팅액 제거 |
| 도박 승리 | 베팅액의 두 배 지급, 원금을 포함하므로 순변화는 +베팅액 |
| 경찰 벌금 | 현재 잔액의 25% 올림 제거 |
| 무료 놀이 | 공금 변동 없음. 개인 최고 점수만 표시 |

예: 공금 300에서 50 베팅 → 패배 250 / 승리 350. 승률 50%에서는 기대 순변화 `0.5×50−0.5×50=0`이다. 실시간으로 호스트가 잔액을 확인하므로 동시 요청도 이미 쓴 공금을 다시 쓸 수 없다. 도박은 2초마다 가능하며 공금 전부 베팅도 가능하다. 개인 할당량·일일 예산·손실 방지 장치는 없다.

벌금 예: 공금 350에서 체포 → `ceil(350×0.25)=88`, 다음 날 262. 같은 판매나 체포를 중복 정산하지 않는다.

판매는 안정적 수입을 얻지만 다른 낮 활동을 할 시간을 쓴다. 무료 놀이는 위험과 수입 없이 개인 기록을 남긴다. 도박은 빠른 복구 기회와 공금 전체 손실 위험을 동시에 준다. 침입 깊은 곳에서 더 많은 가구를 얻으려면 센서를 통과하고 귀환 시간이 늘어난다. 전원 철수는 안전하게 은행 처리하지만 남은 침입 기회를 포기한다.

## 조작과 설정

- **WASD** 이동. 낮과 밤 모두 본인 캐릭터를 따라간다.
- **E** 가구 들기 / 낮 계산대 판매 / 밤 문과 센서 스위치 / 차량 적재 또는 빈손 철수.
- **Q** 현재 위치에 운반 가구 내려놓기.
- 도박장 근처에서 오른쪽 **베팅** 또는 **공금 전부 베팅** 버튼. 떨어져서 원격 도박은 불가능하다.
- 무료 놀이 기계 근처에서 **타이밍 맞추기 (무료)**. 표시가 가운데일수록 높은 점수다.
- **Esc / 설정** 음량·개별 상대 음량·해상도. 설정이나 베팅 입력 중에는 이동 입력을 차단한다. 온라인 시간은 계속 흐른다.

기존 마스터·음악·효과음, 참가자별 음량과 음소거를 유지한다. 해상도 미리보기는 15초 내 유지 확인이 없으면 이전 설정으로 돌아간다. 음악·효과음 파일은 아직 포함하지 않았다. `Music` AudioSource에 BGM을 연결하거나 `AuctionGame.playMusic` / `playEffect`로 사용한다. 밤에도 동료 이름·색상을 유지하며 음성 변조는 없다.

## 구현과 적용

세 씬은 공통 `Assets/3. Prefabs/AuctionGame.prefab`을 참조한다. `AuctionGame`은 기존 방·음성·설정을 유지하고 실제 규칙은 `FurnitureStore`에 위임한다. 각 담당 구성 요소의 책임은 [ProjectStructure.md](ProjectStructure.md)에 있다.

프리팹 연결은 자동 구성되어 별도 수동 연결이 필요 없다. `CantResell > Set Up Prototype`은 누락된 구성 요소를 추가하고 참조를 연결하며 기존 설정을 보존한다. 변경을 저장하지 않은 씬이 있으면 중단한다. 숫자는 아래 Inspector에서 조정한다.

| 구성 요소 | 조정 항목 |
| --- | --- |
| FurnitureRoundComponent | 날짜 2~4일, 낮/밤 시간 |
| FurnitureEconomyComponent | 시작/목표 공금, 벌금 비율, 도박 승률/간격 |
| FurnitureInventoryComponent | 시작 재고와 집당 가구 수 |
| FurnitureShopComponent | 손님 인내와 입장 간격 |
| FurnitureNightComponent | 경찰 도착·속도·체포 거리, 센서 주기/차단 시간 |
| FurnitureLeisureComponent | 타이밍 왕복 시간 |

호스트가 모든 행동·거리·단계·공금을 판정한다. 캐릭터 입력/위치는 Fusion, 공동 상태는 Reliable Data로 0.2초 간격 및 주요 행동 시 전송한다. 명령의 경기/날짜/단계를 확인하고 오래된 상태 순번을 버린다. 새 방 호환 버전은 5, 메시지 버전은 3이다. 이전 경매 빌드의 방과 섞지 않는다. 현재 방장 퇴장 시 방 종료, 진행 중 재접속·호스트 이전은 제외한다.

## 최소 범위와 플레이 테스트

현재 범위: 가게 하나·집 하나·가구 6종의 임시 모형·동시 4인 이동·주문 판매·공금 도박·무료 놀이·센서 스위치·신고와 경찰·차량 적재/철수·공동 결과. 본게임의 기존 경매·개인 목표·무작위 순차 침입은 활성 규칙에서 제외했다.

검증 후 추가 후보는 집 구조 다양화, 소음과 시야, 두 명이 함께 옮기는 큰 가구, 더 많은 낮 활동이다. 각각 충돌·동기화·경로·규칙 부담을 늘리므로 현재 범위에서 구현하지 않는다. 정식 아트·음악·가격 밸런스·수익화도 미정이다.

| 가설 / 상황 | 관찰·초기 판단 기준 | 결과에 따른 수정 |
| --- | --- | --- |
| 자유 낮 활동이 대화를 만든다. 친구 4명으로 3판 | 운영 요구·변명·도박 책임 대화가 각 판에 생기는지, 강제로 일하게 느끼는지 기록 | 주문 간격·판매 조작부터 조정. 새 활동은 그다음 |
| 잔액 0에서도 복구 선택이 남는다. 시작 직후 전부 손실 | 남은 재고나 다음 밤으로 복구 시도 가능 여부, 무의미한 대기 시간 | 시작 재고와 손님 간격 조정 |
| 도박을 계속해도 사회적 갈등이 놀이로 유지된다 | 반복 도박 탓에 전원이 그만두고 싶어하는지, 실패 후 재도전 의사 | 자유 사용 원칙은 유지하고 판 길이·승률·목표를 재검토 |
| 경보 후 위험 판단이 생긴다. 낮은 재고·높은 공금 각각 시험 | 첫 신고 뒤 적재/철수 선택, 체포 전 경보 이해, 기다리는 철수자의 참여 | 경찰 도착·가구 위치·철수 안내 조정 |
| 20~30분 목표와 협업 난도가 맞는다 | 실제 판 시간, 판매 수, 밤 확보 수, 손실과 최종 잔액 기록 | 낮/밤 시간·목표 공금·가격 조정 |

성공률이나 재미는 자동 검사로 판정하지 않는다. 기본 21분은 제한 시간 계산이며 실제 소요 시간 확정값이 아니다.

## 자동 검증

EditMode `CantResell.Tests`는 공금 정산·잔액/중복/오버플로 경계·운반 쟁탈·적재/몰수·주문·센서·4일/3밤 흐름·실제 씬과 프리팹 참조를 검사한다. 이전 경매 구성 요소의 독립 회귀 검사도 보존한다.

PlayMode `CantResell.PlayTests`는 오프라인 데이터로 Home·StandBy·Play·설정·새 공동 HUD·밤 경보·결과·실제 바닥/외벽 충돌을 검사하고 `Logs/PrototypePreview`에 화면을 저장한다.

`AuctionProjectSetup.buildWindows`는 일반 실행 파일, `buildConnectionSmoke`는 별도 자동 검증 빌드를 만든다. 후자는 `-furniturePeer`, `-furnitureRoom`, `-furnitureDirectory`로 네 프로세스를 실행하여 실제 Photon 연결과 Fusion 입력으로 판매·공유 도박·무료 놀이·동시 침입·가구 적재·철수·경찰 벌금·결과·대기실/퇴장을 검사한다. 자동 입력은 일반 빌드에 포함되지 않는다.

새 주제 이전의 네 프로세스 음성·설정·경매 검증 기록은 Git 이력과 기존 Logs/ConnectionSmoke, SettingsSmoke, GameplaySmoke에 남아 있다. 이는 새 게임의 재미·밸런스가 검증됐다는 근거로 사용하지 않는다. 최신 실행 결과는 아래에 별도로 기록한다.
